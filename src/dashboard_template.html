LLM Ticket Triage with RAG

Support tickets for a fictional online store are classified by Gemini (category, priority, suggested reply), grounded in SOP documents retrieved from Postgres + pgvector. Risky or uncertain tickets go to a human review queue. All data is synthetic.

Method and limits

  • Pipeline: ticket → Gemini embedding → pgvector search over 25 SOP documents → Gemini returns category, priority, confidence and a reply → review rule → Postgres.
  • Review rule: a ticket goes to a person if the predicted priority is High or Urgent, the category is Billing & Payments, model confidence is low, or no SOP matches well.
  • Evaluation: accuracy is measured on tickets labelled by hand before any model output was seen. A fresh test set was kept apart from the tickets used to tune the prompt.
  • Limits: small samples (wide confidence intervals), synthetic tickets, priority is subjective even between two humans, and the model is not reliable enough to run without review.
